# VUDO ERP

Веб-система для VUDO (корпусні меблі на замовлення): замовлення, прорахунок, планування робіт, облік грошей, P&L і аналітика.
Еталон вигляду й поведінки — клікабельний прототип; вимоги — «ТЗ VUDO ERP» v1.0.

## Структура

| Папка     | Що там |
|-----------|--------|
| `shared/` | спільне для сервера й інтерфейсу: статуси, ролі й меню, папки журналу, формати, **формули ТЗ розділу 14** (з автотестами 15.1) |
| `server/` | API на Node.js (Express 5) + PostgreSQL: вхід, сесії, права, журнал. Міграції — `server/migrations/*.sql` |
| `client/` | інтерфейс на React + Vite; стилі перенесені з прототипу |

Усі перевірки прав робить сервер; заборонені поля й записи в API не передаються взагалі.

## Розробка

Потрібно: Node.js 22 або 24 (LTS), PostgreSQL 16+.

```bash
cp .env.example .env          # за потреби змінити DATABASE_URL
createdb vudo_erp
createdb vudo_erp_test        # для автотестів
npm install
npm run create-admin          # перший акаунт власника (пароль запитається в терміналі)
npm run dev                   # API :3000 + інтерфейс http://localhost:5173
```

## Перевірки

```bash
npm test          # автотести формул (shared) і API з реальною тестовою БД (server)
npm run typecheck # перевірка типів усіх пакетів
```

## Робоча система

```bash
npm ci && npm run build
NODE_ENV=production npm run create-admin -- --login owner --name "Ім'я Прізвище"   # перший власник
NODE_ENV=production npm start                                                    # міграції застосовуються при старті
```

- Сервер віддає і API (`/api`), і зібраний інтерфейс. Ставити за HTTPS-проксі (nginx), `TRUST_PROXY=1`.
- Паролі — лише хеш argon2id; сесія — httpOnly-cookie (у БД зберігається тільки хеш токена).
- Резервна копія: щодня `pg_dump` бази + копія папки файлів, зберігати 30 днів (ТЗ розділ 2).
